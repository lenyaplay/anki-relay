# Roadmap

Каждый пункт реализуется через документ требований в `docs/requirements/`
(см. `CLAUDE.md`). По окончании любого пункта — полный прогон
`scripts/validate.py`.

## Этап 0. Процесс — готово

- [x] `CLAUDE.md`: требования перед кодом, обязательная полная валидация.
- [x] Шаблон требований `docs/requirements/TEMPLATE.md`.
- [x] Единая точка валидации `scripts/validate.py` (её же запускает CI).

## Этап 1. MVP — готово, [REQ-001](docs/requirements/REQ-001-mvp.md)

- [x] Конфигурация и валидация при старте.
- [x] Пользователи, коллекции, локи, закрытие по простою.
- [x] Синхронизация: подтягивание, отложенная отправка, бэкофф, SIGTERM, медиа.
- [x] Протокол смены схемы с резервными копиями.
- [x] 39 инструментов MCP.
- [x] OAuth 2.1 + вход через AnkiWeb, страница входа RU/EN.
- [x] Docker, Caddy, пример nginx, CI.
- [x] README (EN/RU).
- [x] Тесты, включая интеграцию с настоящим `anki.syncserver`.

## Этап 2. Проверка в реальном мире — ближайшее

Обратная связь от настоящего AnkiWeb и настоящего Claude — то, чего не дают
автотесты.

- [ ] [REQ-002](docs/requirements/REQ-002-real-world-e2e.md): ручной E2E по
  чек-листу (деплой, коннектор в claude.ai, вход, первая синхронизация, 50 заметок,
  проверка на телефоне, смена схемы с двумя устройствами, отзыв пользователя).
- [ ] Всё найденное — отдельными REQ.
- [ ] Замеры: время первой синхронизации большой коллекции (10k+ заметок,
  гигабайты медиа), размер ответов инструментов в токенах.
- [ ] Какие ошибки реально приходят от AnkiWeb при ограничении частоты;
  откалибровать бэкофф.

## Этап 3. Решения владельца проекта (нужен ответ)

- [x] Автоскачивание при `FULL_SYNC`, если на копии сервера нет неотправленного;
  в остальных случаях — структурированный блок `full_sync` для решения вместе с
  пользователем — [REQ-003](docs/requirements/REQ-003-full-sync-decisions.md).
- [ ] Чтение `.env` при запуске без Docker (сейчас переменные нужно экспортировать).

## Этап 4. Надёжность и эксплуатация

- [ ] SSRF: закрепить разрешённый IP на время запроса (убрать окно DNS rebinding).
- [x] Структурные логи (JSON) с id пользователя, без секретов, и отладочный архив —
  [REQ-004](docs/requirements/REQ-004-logging.md).
- [ ] Расширенный `/health` (состояние синхронизации по пользователям, без PII).
- [ ] Восстановление из резервной копии одной командой.
- [ ] Проверка целостности коллекции (`col.fix_integrity()`).
- [ ] Предупреждение о нехватке места на диске (медиа).
- [ ] Публикация Docker-образа в GHCR по тегу.

## Этап 5. Возможности Anki (по запросам)

- [ ] Отменить последнее действие (`col.undo`).
- [ ] Фильтрованные колоды.

- [ ] Импорт/экспорт `.apkg` и CSV.
- [ ] Флаги карточек, пометка заметок.
- [ ] Поиск и замена в полях.
- [ ] Пустые карточки (`get_empty_cards`).
- [ ] Image Occlusion.

## Принципы приоритизации

1. Сохранность данных пользователей важнее новых возможностей.
2. Сначала то, что подтверждено реальным использованием (этап 2), потом догадки.
3. Сервер остаётся тонкой обёрткой над Anki: никаких собственных абстракций.
