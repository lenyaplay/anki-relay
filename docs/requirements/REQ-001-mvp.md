# REQ-001: MVP Anki Relay (MCP-сервер + синхронизация с AnkiWeb + OAuth)

- **Статус:** done (ручная проверка с настоящим AnkiWeb и Claude — REQ-002)
- **Дата:** 2026-10-05
- **Связано:** ROADMAP → «Этап 1. MVP»; исходная спецификация —
  [`REQ-001-spec.md`](REQ-001-spec.md) (перенесена из `PROMPT.md` без изменений).

## Зачем

Дать Claude (claude.ai, десктоп, мобильные приложения) возможность работать с
коллекциями Anki нескольких доверенных пользователей через кастомный
MCP-коннектор, не требуя запущенного Anki Desktop. Сервер — «ещё одно
устройство Anki» со своей копией коллекции, синхронизируемой с AnkiWeb.

## Что меняется

Создаётся проект с нуля в объёме исходной спецификации: инструменты MCP,
синхронизация коллекции и медиа, протокол смены схемы, OAuth 2.1 со входом через
AnkiWeb, страница входа RU/EN, конфигурация, Docker (Caddy / свой nginx),
README на двух языках, CI, тесты.

## Что не меняется (границы)

- Никаких собственных абстракций поверх Anki (пресетов типов, схем тегов).
- Нет веб-интерфейса администратора, нет мультиарендности кроме `ALLOWED_EMAILS`.
- Нет поддержки `mcp` 2.x.

## Проверенные факты об API (anki 26.9.3, mcp 1.30.0)

Проверено через `inspect` и экспериментами на локальном сервере синхронизации
`python -m anki.syncserver` (входит в пакет `anki`).

| Что | Факт |
|---|---|
| Вход | `col.sync_login(username, password, endpoint)`; неверный пароль → `SyncError`, `.kind == SyncErrorKind.AUTH`. Сеть → `NetworkError` |
| Синхронизация | `col.sync_collection(auth, sync_media)` → `SyncOutput` с полями `required`, `new_endpoint`, `server_media_usn`, `server_message`; enum `SyncOutput.ChangesRequired`: `NO_CHANGES, NORMAL_SYNC, FULL_SYNC, FULL_DOWNLOAD, FULL_UPLOAD` |
| Полная синхронизация | `close_for_full_sync()` → `full_upload_or_download(auth=, server_usn=, upload=)` → `reopen(after_full_sync=True)` |
| Новое устройство при непустом сервере | `FULL_DOWNLOAD` (проверено) |
| Пустой сервер + непустая локальная коллекция | `FULL_UPLOAD` → по протоколу это ошибка; в README: аккаунт AnkiWeb должен быть хотя бы раз синхронизирован с Anki Desktop |
| Медиа | `col.sync_media(auth)` возвращается сразу, работает в фоне; `col.media_sync_status()` → `active`, `progress{checked, added, removed}`; бросает исключение, если фоновая синхронизация упала |
| Медиафайлы | `col.media.write_data(name, data)` возвращает итоговое имя; `col.media.check()`; `col.media.trash_files()` |
| Проверка заметки | `note.fields_check()` → `NoteFieldsCheckResult` (`NORMAL, EMPTY, DUPLICATE, MISSING_CLOZE, NOTETYPE_NOT_CLOZE, FIELD_NOT_CLOZE`) |
| Признак смены схемы | `col.schema_changed()` (`scm > ls`) |
| MCP-контекст | `get_access_token()` из `mcp.server.auth.middleware.auth_context` (contextvar, ставится `AuthContextMiddleware`); `AuthorizationCode/RefreshToken/AccessToken` имеют поле `subject` |
| Лимит тела запроса | `FastMCP(max_request_body_size=4 МБ по умолчанию)` — нужно поднять под `MEDIA_MAX_MB` в base64 |
| Проверка Host | `TransportSecuritySettings` действует только на `/mcp` |

### Какие операции меняют схему (эксперимент, с заметками и без)

| Меняет схему (нужна полная выгрузка) | Не меняет схему |
|---|---|
| добавление, удаление, перестановка поля | переименование поля, настройки поля (шрифт, размер, RTL, описание…) |
| **смена поля сортировки** | переименование шаблона, тексты шаблонов, CSS |
| добавление, удаление, перестановка шаблона | создание, клонирование, переименование типа |
| удаление типа | заметки, карточки, колоды, группы настроек, теги, медиа |
| `change_note_type` (для заметок) | |

## Решения и отклонения от исходной спецификации

1. **`sort_field` перенесён** из `update_note_type` в операцию
   `{"op": "set_sort_field"}` инструмента `edit_note_type_schema`: эксперимент
   показал, что смена поля сортировки помечает схему изменённой. Иначе
   `update_note_type` нарушал бы обещание «не меняет схему».
2. `update_note_type` дополнительно принимает `field_options` (шрифт, размер,
   RTL, описание и т. п.) — это не меняет схему, а без этого Claude не может
   сделать всё, что делает пользователь в Anki Desktop.
3. `edit_note_type_schema` выполняет протокол полной выгрузки только если после
   операций `col.schema_changed()` действительно истинно (например, только
   переименования проходят обычной синхронизацией). `dry_run` сообщает
   `requires_full_sync` по проверенной таблице выше; соответствие таблицы
   реальности проверяется тестом.
4. Новая необязательная настройка `SYNC_ENDPOINT` (по умолчанию пусто = AnkiWeb):
   для пользователей собственного сервера синхронизации Anki и для
   интеграционных тестов против настоящего `anki.syncserver`.
5. Помимо тестов с фейком AnkiWeb (как в спецификации) добавлены
   интеграционные тесты против настоящего локального `anki.syncserver`
   (без внешней сети): вход, полное скачивание, обычная синхронизация, протокол
   смены схемы со вторым «устройством», медиа.
6. Проверка заголовка `Host` распространяется на все маршруты (кроме `/health`),
   а не только на `/mcp`.

## Влияние на синхронизацию и данные пользователей

- `upload=True` вызывается ровно в одном месте — в протоколе смены схемы; тест
  сканирует исходники и проверяет поведение.
- Перед сменой схемы — обязательная успешная обычная синхронизация и резервная
  копия; при неудаче выгрузки — флаг `pending_schema_upload`, блокирующий обычную
  синхронизацию.
- Пароль AnkiWeb не сохраняется и не логируется; хранятся только `hkey` и
  `endpoint` (права 600).

## Отклонения и заметки по реализации

1. **Находка интеграционного теста с настоящим `anki.syncserver`:** когда *другое*
   устройство меняет схему и делает полную выгрузку, сервер синхронизации отвечает
   клиенту `FULL_SYNC`, а не `FULL_DOWNLOAD`. По спецификации это ошибка с подсказкой
   `sync(force_download=true)` — так и сделано. Чтобы Claude не боялся этого шага,
   сообщение различает случаи: если на копии сервера нет неотправленных изменений
   (`dirty=false` и `schema_changed()=false`), оно прямо говорит, что скачивание
   ничего не потеряет. Позже заменено автоматическим скачиванием в безопасном
   случае — см. [REQ-003](REQ-003-full-sync-decisions.md).
2. Полное скачивание при обычной работе выполняется автоматически только если на
   копии сервера нет неотправленных изменений; иначе — ошибка с предложением
   `sync(force_download=true)`. Перед любым полным скачиванием уже синхронизированной
   копии делается резервная копия (`*-before-download.anki2`).
3. Флаг `pending_schema_upload` ставится **до** начала выгрузки и снимается после
   успеха — так сбой процесса посреди выгрузки не теряется.
4. После неудачной полной синхронизации коллекция переоткрывается через
   `reopen(after_full_sync=True)` — проверено экспериментом, данные не теряются.
5. Вывод сервера синхронизации в тестах пишется в файл: при чтении через неразобранный
   pipe сервер блокировался на записи логов, и синхронизация зависала на 60 с
   (ложный «таймаут сети»).
6. Отзыв токена через `/revoke` в SDK требует ключ `client_secret` в форме даже для
   публичных клиентов (особенность `mcp` 1.30).
7. Токены в `oauth.json` хранятся как SHA-256, а не в открытом виде.
8. Известное ограничение: проверка SSRF разрешает DNS до запроса, но httpx
   разрешает имя повторно при соединении (теоретическое окно для DNS rebinding).
   Кандидат на доработку в ROADMAP.
9. Каталог `/data` в контейнере: entrypoint стартует от root только чтобы выдать
   права на bind-mount `./data` пользователю `anki` (uid 10001), затем понижает
   привилегии через `setpriv`. Приложение работает не от root (проверяется в
   `validate.py`).
