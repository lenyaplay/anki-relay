# Anki Relay

Self-hosted [MCP](https://modelcontextprotocol.io)-сервер, который подключает Claude
(claude.ai, десктоп и мобильные приложения) к коллекциям Anki нескольких доверенных
людей. Попросите Claude разобраться в коллекции, спроектировать типы заметок,
добавить сотню карточек с картинками и аудио, перетегировать, перестроить колоды
или поправить настройки — изменения придут на телефон и компьютер обычной
синхронизацией Anki.

[English version](README.md)

```
Claude ──HTTPS + OAuth──▶ anki-relay.example.com/mcp
                           │  MCP-сервер + копия коллекции каждого пользователя
                           ▼
                        AnkiWeb ◀──▶ ваш телефон, ваш компьютер
```

**Сервер — это просто ещё одно устройство Anki.** Для каждого пользователя он
хранит на диске свою копию коллекции (`collection.anki2` и папку медиа) и
синхронизирует её с AnkiWeb через официальную Python-библиотеку `anki` — тот же
движок, что в Anki Desktop. Ни Anki Desktop, ни AnkiConnect не нужны.

- Войти могут только адреса из `ALLOWED_EMAILS`.
- У каждого пользователя своя коллекция, своя сессия AnkiWeb и свои OAuth-токены;
  к чужим данным доступа нет.
- Вход — email и пароль от AnkiWeb. Пароль проверяет AnkiWeb, на сервере он не
  сохраняется.

> Неофициальный проект: не связан с Anki, AnkiWeb, Ankitects и Anthropic. AnkiWeb —
> бесплатный сервис; сервер синхронизируется не чаще обычного клиента Anki.

## Требования

- VPS (для нескольких пользователей хватит 1 ГБ RAM; место на диске под коллекции и
  медиа).
- Docker с плагином Compose.
- Поддомен, например `anki-relay.example.com`, с A- (и/или AAAA-) записью на VPS.
- Коллекция каждого пользователя уже должна быть в AnkiWeb (хотя бы раз
  синхронизируйте Anki Desktop или AnkiMobile). Сам сервер никогда не выгружает
  коллекцию в пустой аккаунт.

## Установка

```bash
git clone https://github.com/<you>/anki-relay.git
cd anki-relay
cp .env.example .env
nano .env            # заполните PUBLIC_URL и ALLOWED_EMAILS
docker compose up -d
docker compose logs -f anki-relay
```

### Режим 1: всё из коробки (по умолчанию)

`COMPOSE_PROFILES=caddy` в `.env` поднимает приложение и [Caddy](https://caddyserver.com).
Caddy берёт имя хоста из `PUBLIC_URL` (в Caddyfile адрес сайта — `{$PUBLIC_URL}`),
сам получает сертификат Let's Encrypt и проксирует запросы в приложение по
внутренней сети Docker. Порты 80 и 443 должны быть открыты. Порт приложения на хосте
в этом режиме не нужен и привязан только к `127.0.0.1`.

### Режим 2: свой nginx

`COMPOSE_PROFILES=` (пусто). Поднимается только приложение, опубликованное на
`${BIND_ADDRESS}:${APP_PORT}` (по умолчанию `127.0.0.1:8000`). HTTPS и
проксирование делает ваш nginx — возьмите за основу
[`deploy/nginx.conf.example`](deploy/nginx.conf.example), там объяснена каждая
директива (порт в `proxy_pass` = `APP_PORT`, заголовок `Host`, `X-Forwarded-For`,
настройки потоковых ответов, `client_max_body_size`).

### Порты

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BIND_ADDRESS` | `127.0.0.1` | На каком адресе хоста публикуется порт приложения. `127.0.0.1` — доступно только с самого сервера (nginx на том же VPS). `0.0.0.0` — со всех интерфейсов. |
| `APP_PORT` | `8000` | Порт приложения на хосте (то, что указывается в `proxy_pass`). |
| `HTTP_PORT`, `HTTPS_PORT` | `80`, `443` | Порты Caddy на хосте (только в режиме `caddy`). |

> **`BIND_ADDRESS=0.0.0.0`** делает приложение доступным снаружи по чистому HTTP.
> Включайте только если прокси стоит на другой машине, закройте порт файрволом для
> всех остальных и добавьте адрес прокси в `TRUSTED_PROXIES`.

> **Нестандартные `HTTP_PORT`/`HTTPS_PORT`**: Let's Encrypt проверяет домен только
> на портах 80/443, поэтому на других портах Caddy не получит сертификат обычным
> способом. Такая настройка имеет смысл, если перед Caddy стоит ещё один прокси,
> который пробрасывает к нему 80/443 (внешние порты при этом стандартные), или если
> вы настроили Caddy на DNS-challenge (нужна сборка Caddy с плагином вашего
> DNS-провайдера и правка Caddyfile).

## Подключение к Claude

1. В Claude: **Settings → Connectors → Add custom connector**.
2. Адрес: `https://anki-relay.example.com/mcp` → **Add** → **Connect**.
3. Откроется страница входа вашего сервера: email и пароль от AnkiWeb.
4. Готово. Первый запрос скачивает коллекцию (а медиа — в фоне) с AnkiWeb; для
   больших коллекций это занимает время.

### Как проходит вход (OAuth 2.1)

1. Claude регистрируется как OAuth-клиент (динамическая регистрация) и открывает
   `/authorize` с PKCE.
2. Сервер перенаправляет на свою страницу `/login?req=…` (ссылка живёт 10 минут и
   срабатывает один раз).
3. Вы вводите email и пароль от AnkiWeb. Адреса не из `ALLOWED_EMAILS` отклоняются
   без обращения к AnkiWeb. Иначе сервер просит AnkiWeb проверить данные и при
   успехе сохраняет **только** ключ сессии AnkiWeb (`hkey`) и адрес сервера в
   `data/users/<id>/sync_auth.json` (права 600).
4. Вас возвращают в Claude с одноразовым кодом (5 минут), который Claude обменивает
   на access-токен (`ACCESS_TOKEN_TTL`) и refresh-токен (`REFRESH_TOKEN_TTL_DAYS`,
   меняется при каждом использовании).
5. При каждом запросе сервер проверяет, что email владельца токена всё ещё разрешён.

Клиенты и токены (в виде SHA-256) лежат в `data/oauth.json`, поэтому перезапуск
никого не разлогинивает. Повторные неудачные входы с одного IP блокируются
(`LOGIN_MAX_FAILS` за `LOGIN_FAIL_WINDOW`, плюс общий лимит в 5 раз больше).

## Настройки

Обязательны только `PUBLIC_URL` и `ALLOWED_EMAILS`. **По умолчанию включены все
возможности**; настройки урезают их или ослабляют защиту. Неверное значение
останавливает сервер при старте с сообщением, где названа переменная.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PUBLIC_URL` | — (обязательно) | Внешний адрес без `/mcp`. `https://` (или `http://localhost` / `http://127.0.0.1` для разработки). |
| `ALLOWED_EMAILS` | — (обязательно) | Email-адреса AnkiWeb через запятую. |
| `COMPOSE_PROFILES` | `caddy` | `caddy` — встроенный HTTPS, пусто — свой прокси. |
| `DISABLED_TOOLS` | пусто | Инструменты, которые не регистрировать, например `delete_notes,delete_deck`. |
| `ALLOW_SCHEMA_CHANGES` | `true` | Разрешить перестройку типов заметок (полная выгрузка по протоколу). `false` убирает эти инструменты, и сервер никогда не выгружает коллекцию. |
| `MEDIA_SYNC` | `true` | Двусторонняя синхронизация медиа; при `false` отключён и `add_media`. |
| `MEDIA_ALLOWED_EXTENSIONS` | все форматы Anki | Список расширений или `*`. |
| `MEDIA_MAX_MB` | `100` | Лимит размера одного файла. |
| `MEDIA_DOWNLOAD_TIMEOUT` | `60` | Таймаут скачивания для `add_media(url=…)`, секунды. |
| `MEDIA_ALLOW_PRIVATE_URLS` | `false` | Разрешить скачивание с внутренних адресов (см. «Медиа»). |
| `SYNC_PULL_INTERVAL` | `60` | Подтягивать изменения с AnkiWeb не чаще, чем раз в столько секунд. |
| `SYNC_PUSH_DELAY` | `10` | Отправлять изменения через столько секунд тишины. |
| `SYNC_PUSH_MAX_DELAY` | `60` | …но не позже, чем через столько секунд после первого изменения. |
| `SYNC_ENDPOINT` | пусто | Свой сервер синхронизации Anki вместо AnkiWeb. |
| `BACKUP_KEEP` | `10` | Сколько резервных копий коллекции хранить. |
| `MAX_BATCH` | `500` | Максимум элементов в пакетном вызове. |
| `ACCESS_TOKEN_TTL` | `3600` | Время жизни access-токена, секунды. |
| `REFRESH_TOKEN_TTL_DAYS` | `90` | Через сколько дней без использования придётся войти заново. |
| `LOGIN_MAX_FAILS` | `10` | Неудачных входов с IP за окно до блокировки. |
| `LOGIN_FAIL_WINDOW` | `900` | Это окно, секунды. |
| `COLLECTION_IDLE_MINUTES` | `30` | Закрывать коллекцию после стольких минут простоя. |
| `DEFAULT_LANGUAGE` | `auto` | Язык страницы входа: `auto` (по браузеру), `ru`, `en`. |
| `TRUSTED_PROXIES` | `127.0.0.1/32,::1/128,172.16.0.0/12` | Каким прокси доверять `X-Forwarded-For` (localhost и сети Docker). |
| `BIND_ADDRESS` | `127.0.0.1` | См. «Порты». |
| `APP_PORT` | `8000` | См. «Порты». |
| `HTTP_PORT`, `HTTPS_PORT` | `80`, `443` | См. «Порты». |
| `HOST`, `PORT` | `0.0.0.0`, `8000` | Где слушает приложение внутри контейнера; нужно только без Docker. |
| `DATA_DIR` | `/data` | Папка с данными. |
| `LOG_LEVEL` | `INFO` | Пароли, токены, email и содержимое карточек не пишутся в логи ни на каком уровне. |
| `LOG_DIR` | `/logs` | JSON-логи (смонтированы в `./logs`); пусто — только stdout. |
| `LOG_RETENTION_DAYS` | `14` | Сколько дней хранить файлы логов. |
| `ANKI_RUST_LOG` | `off` | Собственный лог библиотеки `anki` (`off`…`trace`) в `logs/anki-rust.log`. |

«Урезанная» конфигурация — без удалений, сброса, смены схемы и медиа:

```ini
DISABLED_TOOLS=delete_notes,delete_deck,forget_cards,delete_media
ALLOW_SCHEMA_CHANGES=false
MEDIA_SYNC=false
```

## Инструменты

Сервер — тонкая обёртка над Anki в терминах самой Anki: никаких пресетов,
встроенных типов заметок или схем тегов. Пакетные инструменты принимают списки и
отчитываются по каждому элементу. Списочные принимают `limit` и `offset`. Опасные
инструменты по умолчанию работают с `dry_run=true` и только показывают, что
изменится.

## Как устроена синхронизация

Сервер ведёт себя как обычный клиент Anki и не делает лишних запросов (типичная
серия — 20–60 заметок за полчаса):

- **Подтягивание.** Перед инструментом, который работает с коллекцией, сервер
  синхронизируется, если последняя успешная синхронизация была раньше, чем
  `SYNC_PULL_INTERVAL` назад. Серия вызовов даёт одну синхронизацию, а не по одной
  на вызов.
- **Отправка.** Изменения запускают таймер: через `SYNC_PUSH_DELAY` секунд без новых
  изменений одна синхронизация отправляет всю серию; при непрерывных изменениях
  отправка всё равно происходит не позже `SYNC_PUSH_MAX_DELAY` после первого.
  Вместе с отправкой запускается синхронизация медиа.
- **Остановка и перезапуск.** При `docker compose down`/SIGTERM неотправленные
  изменения отправляются (на это есть 60 секунд); если что-то осталось, оно
  отправится при следующем старте.
- **Ошибки и ограничения частоты.** Ошибки сети и AnkiWeb повторяются с
  экспоненциальной паузой (5 с, 10 с, 20 с … до 5 минут). Тем временем инструменты
  работают с копией на сервере и сообщают об этом. Состояние видно в `sync_status`.
- **Полная синхронизация.** При обычной работе сервер никогда не выгружает
  коллекцию целиком. Когда AnkiWeb отвечает требованием полной синхронизации
  (интеграционный тест показывает это, например, после перестройки типа заметок
  на другом устройстве), сервер решает так:

  | Ситуация | Что происходит |
  |---|---|
  | На копии сервера нет ничего, чего нет в AnkiWeb (нет неотправленных изменений и локальной смены схемы) | Сервер сам скачивает коллекцию из AnkiWeb, сделав резервную копию; ничего не теряется. В ответе инструмента — предупреждение. |
  | На копии сервера есть неотправленные изменения | Ошибка со структурированным блоком `full_sync` (`safe_to_download: false` …). Claude пересказывает, что будет потеряно, и вызывает `sync(force_download=true)` только после вашего подтверждения. |
  | AnkiWeb отвечает `FULL_UPLOAD`, то есть предлагает только выгрузку (`download_offered: false`; в тестах так было, когда коллекция в AnkiWeb пустая) | Никогда не обрабатывается автоматически: сервер не выгружает. Решаете вы; `sync(force_download=true)` заменит копию сервера тем, что есть в AnkiWeb. |

  Пока ситуация не разрешена, тот же блок `full_sync` показывает `sync_status`.
  Скачивание заменяет только копию сервера; AnkiWeb и ваши устройства не
  затрагиваются.

## Изменения схемы

Некоторые структурные изменения Anki не умеет передавать обычной синхронизацией:
добавление, удаление и перестановка полей и шаблонов карточек существующего типа,
смена поля сортировки, удаление типа и смена типа у заметок. После такого изменения
Anki Desktop предупреждает, что «потребуется односторонняя синхронизация»:
коллекция целиком выгружается в AnkiWeb, а все остальные устройства должны её
скачать. (Создание, клонирование и переименование типов, переименование полей и
шаблонов, правка CSS, текстов шаблонов и настроек полей этого **не** требуют.)

Сервер разрешает изменения схемы только по протоколу:

1. Claude вызывает инструмент с `dry_run=true` (по умолчанию) и показывает, что
   изменится, с предупреждением.
2. **Сначала синхронизируйте все устройства**, затем подтвердите. Повторения, не
   отправленные с других устройств к этому моменту, пропадут.
3. При `dry_run=false` сервер сначала делает обычную синхронизацию; она должна
   пройти без требования полной синхронизации, иначе ничего не меняется.
4. Сервер делает резервную копию файла коллекции в `data/users/<id>/backups/`
   (хранятся последние `BACKUP_KEEP`), применяет изменение и сразу выгружает
   коллекцию в одну сторону.
5. На каждом другом устройстве при следующей синхронизации выберите **«Скачать с
   AnkiWeb»**.

Если выгрузка не удалась, изменение остаётся в копии сервера, а обычная
синхронизация приостанавливается, пока `sync()` не повторит выгрузку (или
`sync(force_download=true)` не отменит изменение). Об этом сообщают `sync_status` и
все инструменты.

**Восстановление из резервной копии:** остановите сервер
(`docker compose stop anki-relay`), скопируйте файл из `data/users/<id>/backups/`
поверх `data/users/<id>/collection.anki2`, запустите сервер и, если нужна версия из
AnkiWeb, попросите Claude выполнить `sync(force_download=true)`. Резервную копию
можно и просто открыть в Anki Desktop — это обычный файл коллекции.

**Отключение:** `ALLOW_SCHEMA_CHANGES=false` убирает `edit_note_type_schema`,
`delete_note_type` и `change_note_type`, и сервер больше никогда не выгружает
коллекцию.

## Медиа и место на диске

- Синхронизация медиа двусторонняя, как в Anki: **при первом входе на сервер
  скачиваются все медиафайлы пользователя**, а это могут быть гигабайты. Проверьте
  свободное место или задайте `MEDIA_SYNC=false` (это отключит и `add_media`).
- `add_media` принимает URL или base64, до `MEDIA_MAX_MB`, в форматах, которые Anki
  умеет показывать или проигрывать (`MEDIA_ALLOWED_EXTENSIONS`, `*` — любые). Он
  возвращает итоговое имя и вставку для поля: `<img src="…">` или `[sound:…]`.
- SVG не санируется: поля заметок и так принимают произвольный HTML, поэтому
  отдельная санация SVG ничего не даёт.
- Скачивание по URL — только http/https, не больше 5 редиректов, таймаут
  `MEDIA_DOWNLOAD_TIMEOUT`. **Защита от SSRF** включена по умолчанию: имя хоста
  разрешается заранее, а приватные, loopback, link-local адреса и адреса метаданных
  облаков (`169.254.169.254` …) запрещены — на каждом редиректе.
  `MEDIA_ALLOW_PRIVATE_URLS=true` позволяет брать файлы с NAS или других сервисов
  вашей сети, но тогда всё, что может влиять на Claude в ваших чатах (например,
  веб-страница или документ со скрытыми инструкциями), сможет заставить сервер
  запросить внутренние адреса и сохранить ответы в коллекцию. Включайте, только если
  во внутренней сети по HTTP не доступно ничего чувствительного.

## Безопасность

- Пароли не хранятся и не логируются. Ключи сессий AnkiWeb хранятся в `data/` —
  берегите эту папку (и её резервные копии) как пароль.
- Добавляйте в `ALLOWED_EMAILS` только тех, кому доверяете: администратор сервера
  технически может читать и менять их коллекции.
- **Отозвать пользователя:** уберите email из `ALLOWED_EMAILS` и перезапустите
  (`docker compose up -d`) — токены перестанут работать сразу. При желании удалите
  `data/users/<id>/` (`<id>` — первые 16 hex-символов SHA-256 от email в нижнем
  регистре).
- **Разлогинить всех:** удалите `data/oauth.json` и перезапустите.
- Сервер сверяет заголовок `Host` с `PUBLIC_URL` (защита от DNS rebinding) и
  принимает браузерные Origin только от `claude.ai` / `claude.com`.

## Логи и отладка

Логи можно прочитать только на самом сервере: ни HTTP, ни MCP их не отдают.

- **В реальном времени:** `docker compose logs -f anki-relay` (читаемый текст).
- **Файлы:** `./logs/anki-relay.log`, по одному JSON-объекту на строку, новый файл
  каждый день (UTC), хранятся последние `LOG_RETENTION_DAYS` (14) дней. Каждый вызов
  инструмента пишет запись `tool.call`: инструмент, id пользователя, длительность,
  исход, аргументы *без содержимого* (названия колод, типов, полей и тегов и
  поисковые запросы сохраняются; значения полей, base64, тексты шаблонов и CSS
  заменяются их длиной) и числа из ответа. События синхронизации (`sync.*`) и входа
  (`auth.*`) несут id пользователя, а события синхронизации внутри вызова — его
  `call_id`. Пароли, токены, ключи AnkiWeb, email и содержимое карточек не пишутся
  никогда; последний фильтр вычищает всё, что похоже на секрет.
- **Отладочный архив** для разбора проблемы:

  ```bash
  docker compose exec anki-relay anki-relay debug-bundle          # --days 3 — ограничить
  docker compose cp anki-relay:/logs/debug-bundle-<time>.tar.gz .  # затем scp к себе
  ```

  В нём логи, версии, конфигурация (email заменены на id пользователей), состояние
  синхронизации каждого пользователя, размеры коллекции и медиа и список резервных
  копий. Ключей AnkiWeb, OAuth-данных, коллекций и медиа в нём нет никогда.
- **Диагностика синхронизации.** Каждое обращение к серверу синхронизации пишет
  запись `sync.request`: шаг (`meta`, `full_download`, `full_upload`,
  `media_start`), хост, номер попытки, длительность, а при ошибке — её текст ровно
  так, как его выдала библиотека `anki` (`error_type`, `error_kind`,
  `error_message`, а также `http_code` и `http_context`, если текст имеет вид
  `HttpError { code: …, context: … }`). Ничего не толкуется. `sync.recovered` —
  первый успех после ошибок, `sync.media_failed` — ошибка синхронизации медиа.
- **Собственный лог библиотеки `anki`.** `ANKI_RUST_LOG=debug` (по умолчанию `off`)
  пишет `./logs/anki-rust.log` (предыдущий запуск сохраняется как `.1`; строки
  дублируются и в `docker compose logs`). На `debug` там видны метаданные
  синхронизации обеих сторон, решение о полной синхронизации (`upload_ok` /
  `download_ok`) и сетевые ошибки; тесты проверяют, что пароля, ключа AnkiWeb и
  email там нет. HTTP-ответы (статус, заголовки, тело) не видны ни там, ни где-либо
  ещё: библиотека их не отдаёт. Включайте на время разбора проблемы.

id пользователя — первые 16 hex-символов SHA-256 от email в нижнем регистре, например
`python3 -c "import hashlib;print(hashlib.sha256(b'me@example.com').hexdigest()[:16])"`.

## Разработка

```bash
python -m pip install uv
python -m uv venv -p 3.12 .venv
python -m uv pip install --python .venv -e ".[dev]"
.venv/bin/python scripts/validate.py      # Windows: .venv\Scripts\python scripts\validate.py
```

`scripts/validate.py` запускает всё: ruff, весь набор тестов (включая интеграционный
тест против настоящего локального `anki.syncserver`, который играет роль AnkiWeb),
проверку репозитория на секреты, `docker compose config` для обоих режимов, сборку
Docker-образа и смоук-тесты контейнера. Запускайте его целиком после каждого
изменения. Изменения начинаются с документа требований в `docs/requirements/`
(см. `CLAUDE.md`); план — в `ROADMAP.md`.
