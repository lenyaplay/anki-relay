# Anki Relay — правила работы для агентов и контрибьюторов

Self-hosted MCP-сервер, который даёт Claude доступ к коллекциям Anki нескольких
доверенных пользователей и синхронизирует их с AnkiWeb через официальную
библиотеку `anki`. Обзор и установка — в `README.md` / `README.ru.md`, план —
в `ROADMAP.md`.

## 1. Любое изменение кода начинается с документа требований

1. Перед правкой кода создай `docs/requirements/REQ-NNN-<slug>.md` по шаблону
   `docs/requirements/TEMPLATE.md` (следующий свободный номер), либо обнови
   существующий REQ, если изменение — его прямое продолжение.
2. В документе: зачем, что меняется, что **не** меняется, критерии приёмки
   (каждый — проверяемый, желательно тестом), влияние на синхронизацию и данные
   пользователей, план проверки.
3. Только после этого — код и тесты. Тест на каждый критерий приёмки.
4. По завершении: статус REQ → `done`, отметить выполненные критерии, внести
   отклонения от плана, обновить `ROADMAP.md`.

Исключение — опечатки в документации и комментариях.

## 2. По окончании работы обязательно запускать ВСЮ валидацию

Тесты и проверки — это обратная связь от реального мира (реальная библиотека
`anki`, реальный MCP SDK, реальный Docker). Они влияют на очень многое, поэтому
**в конце каждой задачи запускается полный набор, а не выборочные тесты**:

```bash
.venv/Scripts/python scripts/validate.py      # Windows
.venv/bin/python scripts/validate.py          # Linux/macOS
```

Скрипт выполняет: `ruff check`, `ruff format --check`, `pytest` (все тесты),
проверку на секреты и запрещённые файлы в git, `docker compose config` для обоих
режимов (с профилем `caddy` и без) с проверкой публикации портов,
`docker build` и проверку, что контейнер без обязательных переменных падает с
понятной ошибкой. Если Docker недоступен, шаги Docker помечаются как `SKIPPED` —
это нужно явно сообщить пользователю, а не выдавать за успех.

Отчёт о работе содержит фактический вывод итоговой таблицы `validate.py`.
Если что-то красное — работа не закончена.

## 3. Данные пользователей бесценны

- Никаких путей к `full_upload_or_download(upload=True)`, кроме протокола смены
  схемы в `sync.py` (есть тест, который это проверяет).
- Пароли, токены и содержимое карточек не пишутся в логи ни на каком уровне.
- Не полагайся на память об API `anki` и `mcp`: проверяй сигнатуры через
  `inspect` в `.venv`. Версии зафиксированы в `pyproject.toml`.
- `import anki.collection` — до `from anki.notes import ...`.

## 4. Тексты без догадок

Всё, что уходит в Claude или пользователю (ошибки, предупреждения, описания
инструментов, страница входа), содержит только:
1. что дословно вернула библиотека `anki` или сервер синхронизации;
2. факты о состоянии копии сервера;
3. что делает каждое доступное действие.

Никаких предположений о причинах («вероятно», «обычно», «AnkiWeb недоступен»).
Это проверяет `tests/test_messages.py`. В логах — тоже только факты: исходный текст
ошибки и буквально извлечённые из него поля.

## Окружение

```bash
python -m uv venv -p 3.12 .venv
python -m uv pip install --python .venv -e ".[dev]"
```

Код: `src/anki_relay/`, тесты: `tests/`, деплой: `deploy/`, требования:
`docs/requirements/`.
